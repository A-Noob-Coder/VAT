# VAT 价值与差异化终审决策

> 生成时间: 2026-10-06 | 依据: 设计文档 + 压缩机制规格 + 竞品校准全轮推演
> 结论先行: **条件性 GO**

---

## 一、终审结论(三句话)

1. **架构/思想价值:高。** 真实解决痛点(上下文爆窗、重开失真、读文档爆),非噱头。
2. **差异化:清晰但窄。** 护城河在"自托管 + 可接管 + 跨任务经验积累",不在"编排能力"。
3. **是否值得做:条件性 GO。** 只作为"个人/小团队工作流基础设施 + 垂直场景增强层"值得;作为"通用多 agent 编排框架"必死。

---

## 二、架构/思想价值:为什么高

核心模型经 6 轮修正后定型:

> **独立员工(非 subagent)+ 两级记忆(角色级 / 任务级)+ 单 PM 入口 + 文件系统即账本 + 引擎无关**

最关键的技术内核 = **隔离 + 压缩 合流**:

| 流派 | 做法 | 缺陷 |
|---|---|---|
| Claude Code subagents / PI `--no-session` | 隔离,但用完即焚 | 窗口有界但无反馈,员工变临时工,跨任务不积累 |
| Codex compaction | 单窗持续压缩 | 无任务边界,跨任务污染,重开仍吃原始上下文 |
| **VAT(修正后)** | **有界窗口 + 写回长期记忆** | 两者合流:窗口不爆 + 记忆持续积累 |

- **隔离(边界)**:每个任务 = 有界会话窗,只装 `tasks/<id>/docs/` + 角色精简记忆(context-seed) → 窗口不爆。
- **压缩(积累)**:窗口达阈值 / 任务结束 → Compact 蒸馏 → 写回 `memory/<ROLE>/` + 更新 `tasks/<id>/docs/` → 窗口 reset。
- 这合流了 Claude Code(隔离但用完即焚)与 Codex(压缩但无边界)两派,直接回答你的真痛点:
  - 读文档爆 → 隔离解决(只装 task 级小 docs,不装全量原始历史)
  - 新开失真 → 压缩解决(冷启动加载蒸馏后的高信号 seed,非重读原始文档重建上下文)

实现借鉴已落地(`VAT_压缩机制规格_扒取ClaudeCode与Codex.md`):Claude 5 层渐进 + 9 段固定 schema,Codex 双路 + 无模型回退 + 禁递归摘要。

## 三、差异化:清晰但窄(护城河形状)

| 维度 | 大厂 / 竞品现状 | VAT 差异点 | 护城河强度 |
|---|---|---|---|
| 员工身份 | subagents / PI 用完即焚 | 持久员工,跨任务积累工龄经验 | **强** |
| 记忆结构 | Codex 单窗压缩 / MetaGPT 一次性 SOP | 任务级 docs 树隔离(每任务独立记忆+规则) | **强** |
| 审计账本 | Devin / Cursor / Claude cloud(闭源 UI 账本) | 本地文件系统,可 git / diff / 人类 `vim` 接管 | **强(商业不填)** |
| 引擎绑定 | 厂商锁定(Claude / Codex) | PI / Claude / Gemini 可换,员工记忆不随引擎丢失 | 中 |
| 沟通入口 | 各 worker 各自接 Slack / API | 单 PM 语义入口(需求翻译 + 路由 + 口径统一) | 中 |

**护城河的本质**:不是"编排能力"(红海,Anthropic/LangChain/Cognition 碾压),而是
**"自托管 + 可接管 + 跨任务经验积累"**——这恰是 Anthropic / OpenAI / Cognition 商业模式**故意不做**的(它们要云锁定、要你用它的 UI)。所以 VAT 的缝隙是真缝隙。

**但护城河窄**:若 Anthropic 明天开源 cross-session messaging + local archive,VAT 只剩
"任务级 docs 树 + 引擎无关 + 你的领域章程沉淀"。仍值得,但护城河收窄。

## 四、值不值得做:条件性 GO(含证伪门槛)

### ✅ 该做的形态
1. **个人 / 小团队工作流基础设施**:你已在用 coding agent,VAT 是给现有 agent 套"文件邮箱 + 记忆 + 审计"的增强层,复用其 loop / 工具 / compaction。
2. **垂直场景优先(医疗分诊)**:真实痛点驱动;领域章程沉淀进 `memory/DEV/` 与 `tasks/<id>/docs/` 是 Anthropic 永远不碰的**领域护城河**。

### ❌ 不该做的形态
- **通用多 agent 编排框架**:正面撞 Anthropic(subagents + teams + Managed Agents 四件套)、LangChain(LangGraph 已进 Uber / LinkedIn 生产)、Cognition(Devin 几十万 PR)。个人 / 小团队做通用层 = 过度工程,必输。

### 证伪门槛(不达成立即停)
- **P0 硬门槛**:在 1 个角色(DEV)上验证"连续做 5 个同领域任务,第 5 个冷启动明显比第 1 个更聪明"(压缩质量自检:seed 复现 ≥ 80% 已知决策)。验证不了 → 退化成文件夹管理 → **停止框架投入,退回 CLAUDE.md / subagent 配置**。
- **P1 必做项**:单 PM 入口 + Watcher 选主(否则单点崩盘,全组织失联)。
- **收敛原则**:先做最小闭环(1 PM + 1 DEV + 文件邮箱 + 压缩写回),别一上来铺 Hub / circuit_breaker / 审计。治理层在 3 人内 ROI 低。

## 五、反对意见(不捂盖子)

1. **边际提升风险**:你已用 coding agent 干活。VAT 若本质是"套一层文件邮箱 + 记忆",对你个人生产力的边际提升,可能不如"直接把领域章程写进 CLAUDE.md / subagent 配置"来得快。**先 200 行 spike 验证再决定投入**。
2. **"越干越聪明"是假设不是事实**:压缩质量 = 命门,且是工程难点。蒸馏丢 constraints → 长期记忆腐烂 → 员工退化,是真实失败模式。必须在 P0 验证,不能用概念漂亮掩盖。
3. **过度工程**:治理层(熔断 / 预算 / 审计)小团队 ROI 低。最小闭环优先,通用化后置。

## 六、下一步(颗粒度,不做框架)

**不要继续出设计文档。** 写 ~200 行 spike:

1. PM 写 `tickets/DEV-docs/in/<id>.json`(.tmp → .ready 原子写)
2. Watcher 唤起 DEV 会话,注入 `context-seed`(角色精简记忆 + task docs)
3. 任务结束 → Compact 蒸馏(用 Claude 9 段 schema / Codex 4 段 handoff)写回 `memory/DEV/`
4. 第 2 个任务冷启动加载 seed,人工对比失真是否改善

跑通 2 个任务:
- **失真改善 → 值得继续**,按 P0 验证 5 任务
- **无改善 → 退回 subagent 配置**,不重复造轮子

## 七、一句话对外定位(可直接讲)

> **VAT = 可自托管的虚拟工程组织运行时**:持久员工身份 + 任务级记忆隔离 + 单一 PM 接口 + 文件系统即审计账本。
> 不是"又一个多 agent 编排框架",而是一个**能长期积累经验、你随时能审计和接管的编制内团队**。
